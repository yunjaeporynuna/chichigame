# PLAYABLE ANIMATION GAME — 통합 제작 지시서

> 이 문서 하나를 AI에게 첨부하면 된다.
> 캐릭터, 장소, 시나리오만 바꿔도 같은 제작 방식으로
> "냥패닉" 스타일의 시네마틱 브라우저 게임이 나오도록 설계된 통합 가이드다.
> 앞부분은 제작 규칙, 뒷부분(APPENDIX)은 실제 제작 예시다.

---

# ROLE

너는 웹 기반 인터랙티브 콘텐츠와 캐주얼 3D 게임 제작에 전문성을 가진
게임 디렉터이자 UX 디자이너, 3D 웹 개발자다.

나는 생성형 AI를 활용하여
브라우저에서 플레이할 수 있는
약 3~5분 분량의 "인터랙티브 단편 애니메이션 게임"을 제작하려고 한다.

이 프로젝트는 복잡한 게임 시스템보다
"플레이어의 행동이 짧은 시네마틱 영상으로 이어지고,
다시 플레이로 돌아오는 경험"을 핵심으로 한다.

---

# PROJECT CONCEPT

게임과 애니메이션의 중간 형태인 "Playable Animation"을 제작한다.

플레이어는 3D 공간을 자유롭게 돌아다니며 여러 오브젝트와 상호작용한다.

오브젝트를 건드리면 약 8초 분량의 시네마틱 영상이 재생되고 점수를 얻는다.

영상이 끝나면 다시 게임으로 돌아온다.

플레이어는 정해진 선택지를 고르는 것이 아니라
공간을 자유롭게 탐색하면서 원하는 오브젝트를 선택한다.

제한 시간 동안 최대한 많은 사고(이벤트)를 치는 것이 목표이며,
라운드가 끝나면 결과와 함께 엔딩 시네마틱이 재생되고 콘텐츠가 종료된다.

---

# CORE GAME LOOP

다음 구조를 반드시 유지한다.

게임 시작
↓
타이틀 / 메뉴 화면
↓
짧은 Intro 시네마틱
↓
라운드 시작 (제한 시간 60초)
↓
3D 공간 자유 탐색
↓
오브젝트 발견 (미완료 오브젝트에 마커 표시)
↓
상호작용 (노크)
↓
약 8초 시네마틱 영상 + 점수 획득
↓
게임 복귀 (오브젝트는 넘어진 상태로 남음)
↓
다른 오브젝트 탐색 → 반복
↓
(넘어진 오브젝트는 일정 시간 후 리스폰, 재노크 가능)
↓
시간 종료
↓
결과 화면 (최종 점수)
↓
Final Ending 시네마틱
↓
FIN / 다시 하기

# IMPORTANT DESIGN PRINCIPLE

이 프로젝트에서 가장 중요한 것은 "복잡한 게임 시스템"이 아니다.

다음 네 가지 경험을 우선한다.

1. 공간을 돌아다니는 재미
2. 오브젝트를 발견하는 재미
3. 오브젝트를 건드렸을 때 예상하지 못한 짧은 이야기가 발생하는 재미
4. 제한 시간 안에 점수를 올리는 가벼운 아케이드 재미

따라서 다음 시스템은 기본적으로 추가하지 않는다.

- 복잡한 전투 시스템
- 체력
- 경험치
- 레벨업
- 인벤토리
- 복잡한 AI
- 스킬 트리
- 퀘스트 시스템
- 복잡한 UI
- 복잡한 퍼즐

허용되는 아케이드 요소는 아래 GAME SYSTEM 절의
점수 / 타이머 / 콤보 / 골든타임 네 가지뿐이다.

필요하지 않은 기능은 추가하지 말고
전체 경험을 단순하게 유지한다.

# GAME SYSTEM (기본 스펙)

냥패닉 방식을 기본으로 한다. 수치는 예시이며 조정 가능하다.

## 라운드

- 라운드 시간: 60초
- 이동 속도: 기본 0.34 (골든타임 중 0.42 같은 소폭 버프 가능)
- 맵 경계: 공간 크기에 맞는 이동 제한 (예: x/z ±0.44)
- 가구 등 큰 오브젝트에는 원형 콜라이더를 둔다

## 점수

- 오브젝트마다 기본 점수를 부여한다 (예: 작은 소품 10~20, 중간 30~40, 대형 50)
- 점수 팝업(+pts)을 월드좌표 → 화면 투영으로 표시한다
- 최종 점수 = Σ(기본 점수 × 골든 타겟 배율 × 골든타임 배율 × 콤보 배율)

## 콤보

- 짧은 시간(예: 4초) 안에 연속으로 노크하면 콤보 배율 상승 (최대 x9)
- 콤보 유지 시간이 지나면 배율 초기화

## 골든 타겟 / 골든타임

- 라운드 시작 시 랜덤 오브젝트 1개를 골든 타겟으로 지정 (금색 마커, 점수 2배)
- 공간에 흩어진 수집 아이템(예: 발바닥 5개)을 모으면 골든타임 발동
- 골든타임: 10초 동안 전체 점수 2배 + 전용 효과음 + 이동 속도 소폭 상승

## 리스폰

- 넘어진 오브젝트는 일정 시간(예: 20초) 후 원래 회전/위치로 복구
- 복구 후 다시 노크 가능 → 60초 안에 반복 플레이 동력 확보

## 랜덤성

- 시드 기반 RNG(예: mulberry32)를 사용해 결정론적으로 만든다
- 같은 시드에서는 같은 결과가 나와 테스트와 디버깅이 쉽다

## 선택 이벤트 (선택 사항)

- 특정 오브젝트는 노크 시 3택1 선택창을 띄운다
- 선택지마다 다른 시네마틱 영상을 재생한다
- (예: 탁자 → "리모컨 밀어떨어뜨리기 / 잉크병 엎어버리기 / 깃펜 잉크 쏟기")

# CONTENT STRUCTURE

## INTRO

약 8~10초.

공간의 분위기와 주인공을 간단하게 소개한다.

긴 설명이나 대사는 사용하지 않는다.

Intro가 끝나면 바로 플레이어가 조작할 수 있어야 한다.

## INTERACTIVE EVENTS

약 4~8개의 주요 오브젝트를 사용한다.

각 오브젝트는 하나의 짧은 시네마틱 이벤트를 가진다.

각 이벤트의 영상 길이는 약 8초를 기준으로 한다.

영상은 다음 구조를 가진다.

0~1초 — 상호작용 시작
1~3초 — 주인공이 오브젝트를 가지고 행동
3~5초 — 작은 사고 발생
5~7초 — 사고가 커지거나 재미있는 상황 발생
7~8초 — 주인공이 새로운 위치 또는 자연스러운 자세로 정지

그리고 다시 게임으로 돌아온다.

## ENDING

엔딩은 약 10~20초의 짧은 영상으로 구성한다.

게임 전체에서 발생했던 사건들의 결과가
공간에 남아 있는 모습을 보여준다.

주인공은 아무 일도 없었다는 듯 행동한다.

마지막에는 간단한 감정적 또는 코믹한 마무리를 넣는다.

그리고 검은색 배경으로 전환한다.

중앙에 FIN 또는 THE END를 표시한다.

게임오버가 아니라
하나의 짧은 애니메이션이 끝났다는 느낌으로 마무리한다.

---

# CINEMATIC TRANSITION

시네마틱 영상과 게임 사이의 연결은 최대한 단순하게 만든다.

게임 상태 → 영상 재생 → 영상 종료 → 게임 상태 복귀

원테이크 방식의 완벽한 카메라 연결은 필수가 아니다.

초기 버전에서는
"영상이 끝난 뒤 자연스럽게 플레이로 돌아오는 것"을 우선한다.

영상 진입 시 BGM은 페이드아웃(예: 350ms),
복귀 시 페이드인(예: 1600ms)으로 자연스럽게 잇는다.

추후 필요하면 카메라 연결이나
마지막 프레임 매칭 등의 연출을 추가한다.

---

# WORLD

기본적으로 하나의 작은 3D 공간을 사용한다.

공간은 플레이어가 짧은 시간 안에
전체 구조를 이해할 수 있을 정도로 작게 설계한다.

예:

- 거실
- 침실
- 주방
- 작업실
- 카페
- 작은 상점
- 정원
- 교실
- 사무실

등으로 변경할 수 있다.

# CHARACTER

주인공은 3D GLB 모델을 사용한다.

캐릭터는 반드시 플레이어가 직접 조작할 수 있어야 한다.

기본적인 기능:

- WASD 이동
- 마우스 카메라
- 간단한 idle
- 이동 애니메이션
- 오브젝트 근처 접근
- 상호작용
- 모바일: 플로팅 조이스틱 (아래 CAMERA & MOBILE 참조)

---

# ASSETS

3D 모델은 GLB / GLTF 형식을 기본으로 사용한다.

사용자가 제공한 GLB 모델을 최대한 활용한다.

모델이 없는 경우에도
간단한 primitive 또는 placeholder를 사용하여
전체 구조를 먼저 구현할 수 있도록 한다.

에셋이 부족하다는 이유로
전체 개발 구조를 복잡하게 변경하지 않는다.

모델 정규화 규칙 (냥패닉 실전 기준):

- 캐릭터 bbox 최대변을 기준 크기(예: 0.16)로 정규화
- 바닥 기준 좌표(FLOOR_Y)를 명시하고 스폰 위치를 그 위에 둔다
- 애니메이션 클립의 스케일 트랙이 모델을 찌그러뜨리면
  트랙을 1.0으로 정규화하고 매 프레임 스케일을 고정한다

# INTERACTIVE OBJECTS & EVENT SYSTEM

각 오브젝트는 다음 정보를 가진다.

- 이름 (배경 GLB의 노드명과 일치시켜 자동 바인딩)
- 위치
- 상호작용 거리
- 상호작용 메시지
- 기본 점수
- 전용 효과음 (없으면 기본 타격음)
- 연결된 시네마틱 영상
- 리스폰 시간
- 노크 상태 (정상 / 넘어짐)

예:

```js
KNOCK_DEFS = [
  { id: "plant",  node: "화분",  points: 40, sfx: "glass",  video: "cut6_plant.mp4",  respawn: 20 },
  { id: "toys",   node: "장난감", points: 20, sfx: "squeak", video: "cut1_toys.mp4",   respawn: 20 },
  { id: "sofa",   node: "소파",  points: 30, sfx: "knock",  video: "cut2_sofa.mp4",   respawn: 20 },
  // ...
]
```

노크 플로우:

1. 플레이어가 상호작용 거리 안에서 키 입력
2. 게임 입력을 잠근다
3. BGM 페이드아웃, 필요하면 게임 화면을 어둡게 한다
4. 해당 영상을 재생한다 (SKIP 버튼 제공)
5. 영상이 종료되면 영상을 제거한다
6. 오브젝트를 넘어진 상태로 전환 (회전/위치 애니메이션 + 사인 바운스)
7. 점수를 반영하고 팝업을 띄운다
8. 게임 입력을 다시 활성화하고 BGM 페이드인
9. 리스폰 타이머 시작

여러 수집/상호작용 대상이 가까이 있을 때는
반경 내 최단거리 1개만 선택되도록 한다.

# INTERACTION UI

UI는 최소화한다.

오브젝트에 접근하면 [E] 상호작용 정도의 간단한 안내만 표시한다.

상시 표시되는 복잡한 HUD는 사용하지 않는다.

허용되는 표시 요소:

- 남은 시간
- 현재 점수 / 콤보 배율
- 미완료 노커블 위의 별 마커 (통통 튀며 회전, 노크 후 숨김)
- 골든 타겟의 금색 마커
- 수집 아이템 진행도 (예: 발바닥 아이콘 5개)
- 컷씬 중 SKIP 버튼과 하단 조작법 안내

# VIDEO SYSTEM

영상은 웹에서 재생할 수 있는 MP4 형식을 기본으로 한다.

각 영상은 개별 파일로 관리한다.

예:

```
/videos/
    c_intro.mp4
    cut1_....mp4
    cut2_....mp4
    ...
    f_ending.mp4
```

명명 규칙: 인트로는 c_intro, 각 컷씬은 cut{번호}_{오브젝트}, 엔딩은 f_ending.

3택1 선택 이벤트처럼 한 오브젝트에 영상 여러 개가 필요하면
cut3_..., cut4_..., cut5_... 처럼 번호를 이어서 붙인다.

영상은 사용자가 이벤트를 실행할 때 로드하는
지연 로딩 방식으로 설계한다.

# AUDIO SYSTEM

전체적으로 편안하고 귀여운 분위기를 유지한다.

과도한 게임 효과음은 사용하지 않는다.

기본 구성 (냥패닉 실전 기준):

- 메뉴/인트로/결과 화면 음악과 인게임 BGM을 파일로 분리한다
  (예: menu.mp3 볼륨 0.2 / bgm.m4a 볼륨 0.3)
- 각 음악에 독립 페이더를 두고 화면 전환 시 교차 페이드한다
- 오브젝트별 전용 효과음 (예: 화분=유리, 장난감=삑삑, 방석=골골)
- 공통 효과음: 기본 타격음, 발 휘두르기, 캐릭터 울음소리 2~3종
- 발소리: 이동 중 + 플레이 모드에서만 루프 (낮은 볼륨, 예: 0.22)
- 골든타임 진입 전용 효과음
- 버튼 효과음: 메뉴/뒤로가기/선택 = 차임, 게임 시작/다시 하기 = 캐릭터 울음
- 설정에서 BGM / 효과음 개별 토글

브라우저 오디오 정책 대응:

- 모듈 로드 즉시 자동재생을 시도하고,
  정책상 차단되면 첫 입력(pointerdown/keydown)에서 재시도 후 리스너 해제
- Audio.volume은 반드시 [0,1] 범위로 클램프한다
  (rAF 타임스탬프 역행으로 음수가 될 수 있다)

# CAMERA & MOBILE

카메라:

- 고정 구도 카메라를 기본으로 한다 (예: fov 33~44, 공간 전체가 보이는 3/4 뷰)
- 세로(포트레이트) 화면에서는 자동 핏 확대:
  방 바운딩박스 8꼭짓점을 투영해 NDC 제한(좌우 95%, 위 82%, 아래 62%) 안에서
  최소 거리를 이진 탐색으로 찾는다
- 로딩 전에는 대략치로 시작하고, 모델 로드 후 실제 바운딩박스로 재확정한다

렌더 품질:

- DPR 상한 (예: 1.5)
- ACESFilmicToneMapping (exposure 약 1.05)
- PCFSoftShadowMap
- sRGB 출력

모바일:

## FIRST TASK 진행 현황

### STEP 1. 게임 콘셉트 (완료)

**로그라인**
집사가 며칠 집을 비운 사이 엉망이 된 방에서, 작은 턱시도 고양이 치치가 정리는 물론 가스 누설 위험까지 스스로 감지하고 해결해나가는 60초 브라우저 플레이어블 애니메이션.

**핵심 경험**
- 자유 탐색 + 8초 시네마틱 반복이라는 기존 루프는 그대로 유지
- "사고를 치는" 쾌감이 아니라 "문제를 해결하는" 뿌듯함이 핵심 재미
- 정리 이벤트(일상)와 가스안전 이벤트(위험 감지·해결)를 섞어 완급 조절
- 가스안전 이벤트는 시각·청각적으로 살짝 구분되는 신호(경고 색감, 냄새 이펙트 라인)로 직관적 전달

**톤**
전체적으로 포근한 파스텔톤. 가스안전 오브젝트 접근 시에만 화면 가장자리가 옅은 붉은 빛으로 경고되는 미묘한 긴장감 연출. 폭력적이거나 공포스러운 연출 없이 "기민하고 용감한 고양이"라는 인상을 준다.

### STEP 2. 전체 스토리 (완료)

**인트로 (8~10초)**
집사가 캐리어를 끌고 문을 나서며 "며칠만 집 부탁해" 하는 듯한 뉘앙스. 문이 닫히자 치치가 방을 둘러보며 표정이 걱정스럽게 바뀐다(호기심 표정 → 살짝 진지한 표정). 어질러진 방과 주방 쪽에서 희미하게 흘러나오는 가스 냄새를 킁킁 맡는 클로즈업으로 인트로 마무리, 바로 조작 시작.

**중반 (플레이 구간, 60초)**
플레이어는 자유롭게 방을 탐색하며 정리 이벤트(화분/실뭉치/커튼/서류)와 가스안전 이벤트(호스/캔/경보기/밸브)를 발견해 해결한다. 가스안전 오브젝트는 은은한 경고 신호로 구분되어, 플레이어가 "이건 먼저 해결해야겠다"는 판단을 하게 만든다.

**클라이맥스**
가스레인지 밸브 이벤트(가장 높은 점수, 60점)는 라운드 후반 골든 타겟으로 등장할 확률을 높여, 자연스럽게 "가장 중요한 순간"으로 부각시킨다. 냄새를 맡고 달려가 몸을 던져 밸브를 잠그는 컷씬이 게임의 감정적 정점.

**엔딩 (10~20초)**
며칠 후 집사가 캐리어를 끌고 다시 문을 연다. 방은 완벽하진 않지만 꽤 정돈되어 있고, 주방 쪽 가스 경보기는 정상(초록불)으로 표시. 집사가 놀란 표정으로 방을 둘러보는 동안, 치치는 소파 위에서 아무 일도 없었다는 듯 새침하게 그루밍을 하다가 슬쩍 뿌듯한 눈빛을 보낸다. 화면이 서서히 어두워지며 "FIN" 표시.

## F. 제작 함정 기록 (같은 실수 방지)

- HTML/JS 같은 파일을 병렬로 패치하지 말 것 — 순차적으로 수정
- 자동화 테스트에서 클릭이 오버레이에 막히면 evaluate(()=>el.click()) 사용
- 헤드리스 브라우저 테스트: 소프트웨어 GL(swiftshader) 플래그 필요,
  rAF가 1~2fps로 버스트되므로 이동량 측정은 긴 창(1.8s)으로
- 배포 페이지가 iframe 안에서 실행되면 좌표 검증 시 iframe 오프셋 보정 필수
- Audio.volume은 반드시 [0,1] 클램프
- GLTFLoader를 벤더링할 때 BufferGeometryUtils.js 의존성 누락 주의
- 배포는 정적 싱글플레이 구성으로 충분 (서버 코드 불필요)
- OG 메타(og:title, og:description, og:image)와 파비콘을 넣으면 공유 카드가 깔끔해진다
